## 功能问题

### 1. P1：异步删除使用过期下标，可能错删界面条目或越界崩溃

位置：[HistoryView.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Mine/HistoryView.swift:190)、[WatchLaterView.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Mine/WatchLaterView.swift:126)、[FavoritesView.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Mine/FavoritesView.swift:280)。

三个实现均先保存 `firstIndex`，等待 500ms 菜单退场和 300ms 淡出，再按旧下标 `remove(at:)`。期间另一次删除或刷新可以改变数组，入口也未对同一条目的重复请求做保护。

隔离复现：列表为 A/B/C，间隔 100ms 发起删除 A 和 B。最终界面留下 B，假接口收到的却是删除 A、B，说明 C 被误从界面移走。如果原列表只有 A/B，并且 A 先被移除，B 保存的下标 1 已超出剩余数组范围。后者为由代码和已复现时序推导出的崩溃路径，未在真机上触发。这里的“错删”是界面列表错位，接口仍使用原条目的 ID。

建议：以 ID 锁定正在处理的条目；在真正修改数组时重新定位；回滚前检查是否已由刷新恢复，避免重复插入。不要跨 `await` 保存可变数组的位置。

### 2. P2：断网/超时启动会造成“假退出登录”，恢复网络后不自动恢复

位置：[AccountStore.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Account/AccountStore.swift:29)、[RootView.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/App/RootView.swift:104)。

`isLoggedIn` 完全取决于 `profile != nil`。冷启动 profile 为空，个人资料请求失败时只保留 Cookie，随后结束恢复状态。因此账号凭据仍有效，界面却显示未登录，关注与互动入口也按未登录处理。当前 profile 刷新只在启动恢复和完成登录时调用，没有网络恢复后的重试入口。

隔离验证已确认：模拟网络不可用后，凭据存在、`isLoggedIn == false`、`isRestoringSession == false`。扫码确认后若个人资料请求失败，也可能在登录页关闭后继续显示未登录。

建议：分开表示“有凭据但尚未验证”“已登录”“凭据明确失效”；提供会话恢复重试，并缓存必要的个人资料。

### 3. P2：评论翻页失败后静默停止，当前页面没有重试入口

位置：[CommentsViewModel.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/VideoDetail/CommentsViewModel.swift:189)、[CommentsView.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/VideoDetail/CommentsView.swift:99)。

第一页成功、第二页超时后，catch 将 `hasMore` 设为 false。已有评论时错误占位不会显示，用户看到的只是列表到底了；继续滚动也不会请求。现有 `retry()` 调用的是只允许空列表进入的 `loadInitial()`，直接调用它同样不会立刻重发失败页。

隔离验证已确认：第二页失败后停止分页，随后调用 retry，接口调用次数仍为 2。重新打开整个视频可以重建模型，但切换简介/评论会复用旧模型。

建议：区分“确实到底”与“本页加载失败”；在列表底部提供重试，重试保留旧内容并请求原页码。历史和收藏分页也有把网络失败当成到底的实现，可以一起统一。

### 4. P2：播放中途发生终止错误时，错误信息被隐藏且缺少恢复入口

位置：[InlineVideoPlayer.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Player/InlineVideoPlayer.swift:31)、[PlayerViewModel.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Player/PlayerViewModel.swift:441)。

播放一旦出过首帧，`hasRenderedFirstFrame` 就保持 true。之后 `.error` 仅设置错误和停止状态；界面先进入首帧分支显示控制条，排在后面的错误分支永远进不去。用户可能看到停住的画面和播放按钮，却不知道播放内核已结束当前加载。

首帧后的 buffering 事件也不会形成可见的缓冲状态。播放内核目前只打开一个选定源，已有的 `PlaybackSource.candidates` 没有被用于实际失败重试。

建议：显式区分播放、缓冲、失败；错误状态优先展示，并提供保留进度的重新取流/重试；失败后按需尝试备用地址。此项为代码确认，未注入真机断网故障。

### 5. P2：点赞按钮显示与执行使用不同状态，取消点赞可能变成再次点赞

位置：[VideoDetailViewModel.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/VideoDetail/VideoDetailViewModel.swift:50)、[VideoDetailViewModel.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/VideoDetail/VideoDetailViewModel.swift:112)。

按钮高亮优先读取 `VideoLikeStore`，但 toggleLike 用 `relation?.isLiked` 决定发送赞还是取消赞。关注流刚点赞、详情接口快照仍是未赞时，界面已显示“取消点赞”，点击却发送 `like: true`，计数还会再加 1。详情互动状态尚未返回时也可出现同类问题。

建议：显示、操作及回滚统一读取同一有效状态；互动状态初始请求回来时避免覆盖已经完成的本地动作。此项为代码确认。

### 6. P2：账号切换不清理全局点赞差量

位置：[VideoLikeStore.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Core/Models/VideoLikeStore.swift:15)、[AccountStore.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Account/AccountStore.swift:78)。

全局单例的 key 只有视频 aid，差量优先于任何服务端快照。登出只清 Cookie 和 profile，不清这份单例；登录另一账号后，同一视频仍可能显示上一账号的点赞/取消点赞结果，直到进程重启。

建议：以账号隔离该缓存，或在账号变更时清理，并用会话版本阻止旧请求回写到新账号状态。此项为代码确认，未操作用户账号切换。

### 7. P2：动态刷新与旧分页缺少同一代请求校验，旧响应可能污染新游标

位置：[DynamicFeedModel.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Following/DynamicFeedModel.swift:62)、[DynamicFeedModel.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Following/DynamicFeedModel.swift:87)。

刷新只取消上一次 reloadTask，并未持有或取消正在执行的 loadMore。若旧分页在刷新完成后返回，它仍会追加条目并覆盖 offset/hasMore/page，之后沿旧游标继续请求。外部视图任务可能因回收被取消，但代码本身没有保证它一定取消。快速重刷时，旧 reload 的无条件 defer 还会清除新请求的 loading 标记。

建议：参考 HomeViewModel，为刷新和分页共用请求代号；只允许当前代的结果和 defer 修改状态。此项为静态时序分析，实际 UI 触发概率待真机验证。

## 性能风险与改进

1. **优先处理图片内存预算。** [BiliImage.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Core/UI/BiliImage.swift:122) 按图片张数缓存 UIImage，超过 300 张才全部清空。没有按解码尺寸限制、缩略图降采样或内存压力清理，也没有同 URL 在途请求合并。连续浏览原图/图文动态可能累积很大内存，清空后回滚列表又会重新加载。建议缩略图与原图分层、按像素尺寸降采样、按字节成本逐步淘汰，并合并重复下载。没有实测内存峰值，不能断言已经发生系统内存终止。
2. **测量播放器打开/退出的主线程阻塞。** [MPVPlayerSession.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Player/MPVPlayerSession.swift:283) 从主线程同步等待内核销毁，初始化和部分命令也是同步调用。退出视频、切分 P 时存在卡顿风险。建议先记录真机耗时，再设计串行后台销毁与渲染层寿命管理；不要直接改成不受保护的异步销毁。
3. **检查内联播放的 GPU 成本。** [MPVPlayerSession.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Player/MPVPlayerSession.swift:460) 始终使用全屏横向原生像素 surface，即使只在小播放器中显示。当前设计有保持旋转稳定的收益，应在 Release 真机上比较 GPU 时间与能耗，再决定是否按视频/容器尺寸调整。
4. **减少环境闭包带来的广泛更新。** 编译器对 [ImageViewer.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Core/UI/ImageViewer.swift:30) 和 [CommentThreadView.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/VideoDetail/CommentThreadView.swift:5) 的 `@Entry` 闭包提出依赖可能每次更新都失效的警告。可改为稳定的动作包装器或引用，测量长评论列表的刷新范围后再优化。

## 使用体验建议

- **历史记录续播**：HistoryItem 已解码 progress，但 [HistoryView.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Mine/HistoryView.swift:63) 打开视频时未传递进度。建议显示观看进度并支持继续播放，已看完的视频从头播。
- **搜索结果翻页**：[SearchViewModel.swift](/Users/elsterlee/Alpha/NeoBili/NeoBili/Features/Search/SearchViewModel.swift:69) 固定只请求第 1 页。建议增加分页、总结果或明确的结束提示。
- **播放控制可发现性**：当前播放时中央暂停按钮完全透明，控件出现后也没有暂停图标。建议保留轻量可见的暂停入口，并在缓冲/失败时显示对应状态。
- **定时休眠跨分 P 保留**：计时器属于单个 PlayerViewModel，换分 P/视频会 stop 并取消。若目标是睡前连续听视频，建议将计时放到播放会话层。
- **清晰度设置与请求保持一致**：设置允许 1080P/高码率，但 BiliAPI.playURL 的三组请求均固定 qn=64。DASH 可能返回更高档流，因此不能单凭此处认定 1080P 一定失效；建议按所选清晰度请求，并展示实际选中档位及降级原因，尤其验证 durl 兼容路径。

建议修复顺序：删除安全性 → 登录恢复和评论分页 → 播放失败恢复 → 点赞状态/账号隔离 → 图片内存 → 其余体验与性能测量。
