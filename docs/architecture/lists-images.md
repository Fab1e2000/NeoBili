# 列表、图片与取消

[架构总览](../ARCHITECTURE.md)


画幅/最低时长过滤通过 `VideoDimensionProviders` 适配列表模型；已知信息直接判断，
缺失信息通过 `PortraitVideoStore` 合并查询。补查最多 6 并发，成功缓存 7 天，失败冷却
5 分钟；按批次后台串行持久化，旧快照不能覆盖新快照。过滤关闭或元数据齐全时不补查。

图片消费者共享传输及单份位图 LRU（64 MiB / 300 项）。最后一个消费者退出后取消传输
和排队解码，其他消费者不受影响；内存告警统一清空缓存。已进入 ImageIO 的同步解码
不能中途抢占，取消后不能回填结果。LRU 使用键链接维护访问顺序，命中与单条淘汰不扫描
全部缓存。HTTP 缓存与解码位图缓存分工不同。评论表情同样按消费者合并加载与裁边；原图
单独限制为 16 MiB / 256 项，观察节点仅弱引用位图，缩放缓存区分显示缩放，避免长时间
浏览评论无限保留原图。日期格式化器按模板、语言、时区及日历复用，列表不逐行重新初始化。

图片查看器的分页由固定图片列表决定，与下载和解码状态独立。公开 B 站图片 CDN 默认请求
960 像素边界的预览图，仅点击「查看原图」才请求原图；签名地址和外站地址不改写。
当前页与两侧相邻页独立加载，原图失败保留预览，迟到的预览不会覆盖原图。
查看器独立文件缓存按字节和最近访问淘汰，默认预算 256 MiB、30 天；只在访问、写入和
释放时处理，没有后台轮询。查看器 UUID 与在途请求保护其使用的文件，分享期间继续持有，
关闭后释放；活动图集可暂时超过预算。查看器在下载途中关闭时，迟到下载结束后重新按预算清理。每次下载使用独立版本文件，旧页面解码失败不能
删除同 URL 重试得到的新文件。解码失败回传模型并失效坏文件；有效预览保留，原图和基础
图片均可真正重新下载，不将有 ImageIO 源和帧数视为完整解码成功。
UIKit 分页承载 SwiftUI 加载/失败页及可缩放图片；图片在未放大时不启用平移手势。
ImageIO 在独立 actor 上逐帧解码动图，只有当前前台页播放，远离当前页时释放解码位图。静态图在前后台或分享覆盖时复用已解码位图；分享前后台生成
256 像素预览，系统分享面板使用该预览和完整文件地址，不在按钮回调里解码原图。
评论收起时复用可见正文的六行高度，仅补七行溢出探针；展开后再测量收起高度。
纯文字评论的展开判定按正文、宽度、字号档位和显示缩放缓存，行重新求值时直接命中；
含表情的评论仍现测，因为表情图异步就绪会改变排版。
头像直接提供固定显示尺寸，楼中楼布局标记仅在 Regression 中启用。

搜索输入的联想任务由搜索页持有，不让每次输入触发根页面依赖更新；提交、清空或新联想
请求使旧结果失效。搜索分页维护增量 ID 集合。资料库与全部关注对单页/跨页重复记录去重，
历史以有效且前进的服务端游标继续，收藏按未过滤的原始页长度判断末页。列表过滤结果在
一次 body 内复用，行出现时只判断末尾 ID；重复或过滤页仍提供显式继续入口，失败可重试。
资料库与搜索列表按内容版本、竖屏过滤开关、最低时长和元数据版本复用过滤结果，刷新淡入等
无关的 body 求值不再重扫列表。
公共横向视频卡、相关推荐和直播卡的文字区域随字号增长，正常字号保留原布局。

空评论页记录首次加载完成，重入不重复请求；取消不会消耗首次加载机会。收起视频画面时
弹幕仍跟踪时间但停止逐帧渲染，展开后跳过隐藏期间的积压；seek 使用有序时间轴二分定位。
一级评论和楼中楼的末页判断使用接口返回的独立 ID 覆盖量与页码边界，本地已确认提交及
预览不计入服务端分页覆盖量，避免旧页快照与新提交交错时漏掉尚未获取的评论。回复标题
同时反映已确认的新回复。评论分页只做尾部增量：后续页的评论追加到末尾，新增置顶项补到最前，
已加载的整列不重新拼接；去重集合随分页增量维护。分页触发由父级一次计算，行任务只在
进入或离开末尾窗口时重启。评论行的显示输入是父级一次求值得到的值快照（内容、置顶、
点赞、删除与楼中楼预览），行本身不观察评论模型，输入不变的行由 `Equatable` 跳过重建；
点赞、删除和楼中楼加载只更新相关行的快照。视频页评论区由 `UICollectionView` 承载，
单元格用 `UIHostingConfiguration` 复用宿主并在预取阶段提前下载头像、合并表情请求；
顶部预留仍作为内容内边距参与折叠观察器的偏移换算，不足一屏时用底部内边距补足。
正文展开状态保存在评论模型里，宿主复用或重新配置行时不会丢失；动态详情页的评论仍在
共享滚动区里使用 `LazyVStack`。空间投稿首屏错误支持重试。收藏夹列表本身不提供下拉刷新。手动下拉刷新（稍后再看、历史、收藏夹内的视频、空间投稿与动态）与推荐、直播、关注一致：
`ShortPullRefresh`（触发距离见「浏览 → 滚动与防误触」）触发，`ListRefreshController` 让旧内容淡出、第一页并行取回但暂存，
淡出和请求都结束后一次换入；请求失败恢复旧内容，刷新成功后旧分页响应不能再追加。控制器自己持有任务，列表内容变化不会
取消请求；动画设置中途关闭时只恢复可见内容，不取消请求。关注页换入后按「动态刷新淡入」整列淡入。收藏、历史、稍后再看的卡片
通过 `listEntrance` 与 `videoEntranceIdentity` 使用进入动画，空间页只有退出淡出，
这几个来源都出现在「动画」设置里。
拖动预览复用同一 tile 的裁剪图，旧视频的邻接图预加载不能污染新会话。直播粘包按偏移
读取，避免对每条消息复制整个剩余缓冲区；重连保留仍在窗口里的弱渲染器关联，拆卸时解绑。
直播二进制帧由数据层在解码 actor 上完成 zlib 解压、拆包和 op=5 消息解析，
展示模型只应用解析结果，主线程不再逐条解析原始 JSON。

首页 App 推荐使用原始响应中最后一个有效 `idx` 翻页，在广告、坏卡及本地过滤前提取；
网页推荐独立使用页码。App 下拉刷新保留最近成功响应的自身游标；首次加载、切换来源、
换账号或同账号重登清零。失败不推进游标，刷新失败仍保留原分页请求；缺失或重复的
App 游标停止翻页，仍可手动刷新。过滤后为空的批次也会推进有效游标。

推荐参数集中在 `AppRecommendationProtocol`；当前身份和请求头见[网络与账号](accounts.md)。
`AppRecommendationPage` 解析响应、卡片和游标。当前国际版配置的首次、手动刷新、翻页分别为
`flush=0/14/8`、`pull=1/1/0`；布局请求保留 `flush=2`，首页没有布局切换入口。
`column=2`、`auto_refresh_state=1`、`autoplay_card=11` 等值采用国际版请求模板；
这些字段的动态设置来源仍在[客户端契约](../research/contract/home-feed.md)中单独研究。
`open_event` 按应用生命周期提供 cold/hot，普通请求为空；后台返回保留标记到下一次请求，
缺少已登录账号的 App 凭据时不消耗标记。`banner_hash` 从过滤前的响应横幅取得并在当前
登录会话复用；切换会话清空，旧响应失效。进程重启重新获取。
网络类型来自 `AppNetworkMetadata`，首个系统回调前保持未知；语言和地区使用当前固定模板。
`player_extra_content` 来自屏幕 `nativeBounds` 的长短像素边。

视频轨道选择支持 AVC、HEVC、Dolby Vision 和 AV1 编码前缀，具体取流结果由接口及账号权限决定。
当前渲染层没有显式 EDR/色彩空间接线，画质设置未提供 HDR、杜比视界或 HDR Vivid 选项；
对应输出效果需要独立的设备和素材验收。请求位值、菜单选项和渲染输出分别由所属实现维护。

普通应用优先使用用户在「高级 → 设备编号」保存的 BUVID；留空时使用持久随机编号。
编号在启动时固定，保存后重新打开生效；既有系统派生编号保留供诊断使用。
设备登记、访客和 App ticket 使用该编号的存储作用域，详见[设置开发](../SETTINGS.md#设备编号)。

首页视频保留服务端大卡片标记；`inline_av_v2` 和 large_cover 视频卡占整行，16:9封面，
与普通双列卡混排。过滤或移除卡片留下半行时，展示层把后续最近的普通卡提前补齐，再放入期间的大卡与分隔条；普通卡彼此、大卡彼此仍保持相对顺序，服务端元数据与分页游标不变。没有可配对普通卡时，单卡排在所属批次的大卡之后，不跨到刷新分隔条下方。去重后再次补位，快照、刷新边界及分页触发卡片均按最终展示顺序计算。
连续普通卡共用布局分区，大卡与分隔条形成边界；分隔条与视频卡片一样使用持久 hosting 格子，高度由 `HomeCardLayout.lastSeenHeight` 按文字行高、折行和字号直接给定，不用自适应高度：原生导航栏让列表有了顶部和底部安全区，自适应的分隔条滑进安全区带时会被重新测量，内容高度随之变化，UIKit 在布局里反复改滚动偏移，最终递归到断言终止；`HomeFeedNavigationBarTests` 覆盖这一点。布局回调读取缓存的分区类型，避免逐分区复制数据快照。大卡片标题单行截断，推荐理由使用黄色标签；封面与静音播放共用统计和底部渐变覆盖层，切换画面不改变播放量、弹幕数的位置。原始曝光编号仍取过滤前数组，不取新布局的行号。
`HomeInlinePreview` 在大卡片80%有效视口可见并停留250毫秒后取流，取流成功且请求仍有效时才创建唯一的静音播放器；播放进度由独立进度条视图观察；移除所属窗口也立即停止；
离屏、刷新、切标签、弹窗、后台及打开已有播放会话时停止并取消自己的加载；卡片缺 CID 时，取详情后按实际 CID 取消取流，取消只移除当前预览的共享请求所有权。静音预览使用 null 音频输出，
不激活系统音频会话或 Now Playing。播放器渲染层由仍在窗口中且有效的原容器持续持有；重复创建的可见容器不能在布局回调中互相抢占，原容器失效或播放模式切换后才移交。开始/结束与历史反馈只来自真实首帧后的连续进度，
使用独立播放 session、首页来源from=76/spmid=tm.recommend.0.0、auto_play=2，并保存原卡片track_id。
这些来源值来自 9.13 国际版样本；接口接收和推荐效果分别记录运行结果。

首页本地自动刷新已关闭，不读取服务端间隔来触发请求。返回前台/首页/内容页不会换列表，
手动刷新、分页和账号变化仍触发取数，来源偏好在重新打开应用后生效。
响应 config 提供曝光比例门槛；自动刷新间隔保留解析，不驱动自动请求。
分页与刷新使用请求代号防止旧响应覆盖列表或游标；取消应退出等待而非显示业务错误。
环境动作盒子用于稳定回调身份，闭包只捕获必要 Binding 或独立数据，避免引用宿主形成环。
实际更新次数、帧率、耗时必须运行测量，不从代码结构推断。

首页列表在输入行内容、页头模式和格子环境均未变化时，跳过展平、索引构建与快照比较；
同 ID 内容变化仍重新配置对应卡片。弹幕逐帧推进原地压缩活动轨道，保持存活弹幕的顺序，
避免每帧重建轨道数组；入口尚未让出或静态轨道已满时，在文字测量和位图生成前拒绝弹幕，
滚动弹幕原有的宽度、速度和追尾判定继续保留。

通用的请求合并池、解码并发闸门和内存 LRU 位于 `Core/Caching`，由无业务依赖的 `NeoBiliCore` 模块编译。平台图片管线和 Data 传输消费者显式导入该模块；生产实例与容量仍由 App 组装。

图片传输和文件缓存由 `NeoBiliData` 编译，依赖 `NeoBiliCore` 的通用请求池；位图解码与 UIKit 图片管线仍属于 App 的平台适配。文件缓存只公开查看器需要的加载、释放和失效操作。

关注页默认直播目录使用父模型注入的 streaming 服务；空间页向动态子模型传递同一点赞存储。测试可以为完整父子模型图提供独立状态，普通页面仍使用 App 的生产默认图。

## 浏览与切换的渲染边界

卡片标题的同步显示路径只读取位图缓存，缓存未命中先显示普通文字，再由后台串行队列
生成标题图。预取和显示请求复用缓存；复用卡片在异步结果返回时复核配置与取消状态，
旧标题不能覆盖新内容。首次显示可能在普通文字与位图之间出现轻微换行差异，标题框尺寸不变。

卡片淡入使用原生 opacity 动画，不再为每张可见卡片设置逐帧 TimelineView。入场仍使用
原有单调时钟、动画速度和减少动态效果设置；已经完成入场的复用卡片直接显示。
UP 主页头部折叠值由头部裁切和滚动条边距修饰符观察，列表内容不依赖该逐帧状态。另一分页的头部偏移
在纵向滚动结束或选择分页时同步，避免每帧同时驱动两个滚动容器。
视频页折叠距离由独立观察盒子提供：滚动逐帧只失效播放器区域的裁切与隐藏状态、
收起覆盖层和顶部染色条，简介组件、评论画布与分页容器不随滚动重建。
首页列表的曝光与静音预览在滚动回调中按固定间隔合并采样，滚动停止后补一次最终位置；
头部回弹位移仍逐帧更新，它只改一个格子的 transform。

竖向滚动条沿页面右缘显示。首页手动设置滚动条安全区边距，并关闭 UIKit 的自动叠加；
横向分页仅隐藏水平方向的滚动条，保留内部列表的竖向滚动条。UP 主页和视频页按当前
可见头部设置滚动条顶部边距；内容预留与滚动位置保持独立，折叠、展开和切页时同步更新。

竖向滚动条沿页面右缘显示。首页手动设置滚动条安全区边距，并关闭 UIKit 的自动叠加；
横向分页仅隐藏水平方向的滚动条，保留内部列表的竖向滚动条。UP 主页和视频页按当前
可见头部设置滚动条顶部边距；内容预留与滚动位置保持独立，折叠、展开和切页时同步更新。

评论输入栏以底部 `safeAreaInset` 叠在滚动列表上：列表延伸到玻璃输入栏下方并透出内容，
底部内容边距由安全区在同一次布局中给出，不通过测量高度再回填 scroll content margin。
多行草稿、回复提示和发送错误增加输入栏高度时，底部边距同步增大，滚到底时最后一条评论
仍完整停在输入栏上方；视频页的底部安全区由独立画布传入，动态与回复页沿用系统安全区。

简介中的合集与分 P 入口仅接收标题、总数和当前序号，组件更新比较也只覆盖这些可见字段；
未展示分集的元数据变化不触发入口重绑和自适应高度测量。合集计数按分组累加，当前集序号
直接遍历分组查找，不为折叠入口创建完整的展平数组。完整分集数据仍由选集面板使用。

合集与分 P 面板首次显示时按当前播放条目的稳定 ID 滚动到可见区域中央，并以主题色底与
边框标出正在播放项。首尾条目受滚动边界限制；找不到当前项或当前项被过滤时保持默认位置。
首次定位后保留用户浏览位置；列表内选集更新高亮，重新打开面板重新定位。

选集后面板保持展开，在下层播放器就地切换并开始播放，当前项高亮随播放标识更新。合集
面板保留打开时的数据快照，切片后的详情加载或失败不会清空列表；用户可继续点选或主动关闭。
