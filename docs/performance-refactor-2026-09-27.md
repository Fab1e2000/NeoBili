# 性能重构与误上报修复（2026-09-27）

本轮针对首页加载、图片滚动、元数据缓存、播放地址和观看上报做了可回归的修复。
对照本地 PiliPlus 源码（`a30fcc31043e10cd38c198f47ddd7b23fd6e6163`）理解业务行为；
没有完成两个客户端在同一手机、同一内容、同一
网络下的首帧与掉帧对比，因此不能宣称整机流畅度已经达到或超过 PiliPlus。

## 已修复的问题

| 问题 | 修改后的行为 |
| --- | --- |
| 拖动进度条、暂停/关闭未播放的续播位置也会写历史 | 本地续播与服务端观看分开；只有首帧后、播放中且非缓冲的连续进度才作为观看证据 |
| 心跳按进度差触发，高倍速时更密集，慢请求可乱序 | 首次累计真实观看 5 秒、随后 15 秒；暂停/退出补发真实进度，同账号会话同视频/分 P 共用串行队列，快速重开也不会并发写回 |
| 直接拖到片尾也上传“已看完” | 必须有最后一段真实推进、位置接近已知时长，才能上传完成标记 |
| 旧播放/反馈任务可碰到新账号 | 在用户操作/播放器创建时绑定登录会话，并在取凭据时校验；同账号重新登录也换代 |
| 推荐反馈形式是 GET，被只读请求重试策略误处理 | `/x/feed/dislike` 及撤销禁止自动重试；只接受卡片提供的原因 |
| 访客或旧账号的播放清单被后续登录复用 | 详情、地址和在途请求按会话隔离；迟到响应不能返回或回填新缓存 |
| 旧页面关闭的延迟取消可能打断刚重开的同一视频 | 用播放请求所有者标识取消，只清理对应请求 |
| 快速滚动离屏后下载/解码仍排队 | 每个图片消费者独立退出；最后一个离开才取消共享工作，正在使用同图的卡片不受影响 |
| 同步与异步图片入口各保留一份缓存 | 统一为一份 64 MiB / 300 项 LRU；内存告警清空所有入口 |
| 每条画幅查询都在主线程编码整份缓存 | 按查询批次合并，后台串行编码和持久化；保留取消后在途结果与重启复用 |
| 已取消首页查询仍发请求，刷新动画期间旧卡片触发分页 | 账号查询返回后检查请求版本；新批次提交前阻止分页 |
| 错误响应异构 `data` 掩盖登录失效，异常 WBI 密钥可能越界 | 先识别业务错误；验证密钥长度与十六进制格式；nav 不合并系统 Cookie |
| 普通视频列表没有本地 `isWebRecommendation` 字段时解码失败 | 缺失本地标记时使用 false，保留正常列表与画幅字段解码 |

滑动预取播放地址仍默认关闭。开启时只获取接口元数据，停留 300 ms 后开始，最多
2 个并发、4 个排队。图片预取和正在显示卡片的请求按 UIKit 生命周期交接。

## 可复现的工作量对照

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 已有 1,980 条画幅缓存，再查询 20 条 | 整库写入 20 次 | 整库写入 1 次 |
| 上述场景编码字节数 | 约 3,838,889 B | 192,845 B |
| 图片解码槽位已满，取消 100 个排队请求 | 100 个继续排队，随后仍进入解码 | 队列清空，0 个进入解码 |
| 慢网上待发送的心跳 | 每次独立创建请求任务 | 保留最新待发值，串行发送 |

这些是宿主机上实际生产逻辑的确定性对照，不是手机 FPS 或互联网加载耗时。
画幅缓存耗时受机器负载影响，不作为整机提速百分比。已有图像下采样和续播持久化
优化也重新回归，但不算成本轮新增收益。

- `zsh offline-harness/run.sh`：业务回归通过；新增观看策略 37 项断言、网络 30 项检查

- iPhoneOS `build-for-testing` 与 Release 构建通过，并在连接的 iPhone 17（iOS 27.2）
  上运行 XCTest。
- 真实 4K 播放测试通过：`selectedQuality=120`、轨道和实际解码尺寸均为
  `3840×2160`、`firstFrame=true`、`isPlaying=true`。测试注入空的历史上报器，不提交
  测试视频的观看历史。最终证据在 `DerivedData/RefactorAudit/4k-evidence-final/`。
- 首轮完整真机测试暴露了普通视频解码缺陷及多处过期测试合同：控件可见间距、平铺
  UP 主行高度、默认刷新距离和缺失播放元数据回退。修复了真实解码缺陷，并依据已有
  设计提交更新旧断言，未为测试回退当前界面设计。
- 搜索输入连续性测试用自带输入视图提供合成 marked text，避免手机第三方键盘启动
  时改写测试注入文字；仍检验搜索框身份、焦点、组合文字与候选内容切换。
- 缩略播放器转场测试发现测量误差：失败截图实际中心距目标仅 1 pt，但用截图高度
  线性外推出的中心偏差为 68.7 pt。原生缩放伴随交叉淡入，颜色区域高度不能代表中心
  位置的插值进度；改为检验末三个中间帧的实际中心，保留横向 45 pt、纵向 60 pt
  容差，并检查缩小程度和朝下方缩略窗口运动。产品动画未改变。
- 两项直接写入并清除 `DeviceIdentity.shared` 的旧账号测试不在个人手机执行；它们
  会覆盖正常登录凭据。新会话回归使用注入的假身份。真实账号反馈没有作为自动测试提交。
- 实际网络请求一旦到达服务端便无法撤回；客户端会阻止过期任务继续使用新凭据，
  并避免写操作自动重试。已进入 ImageIO 的同步解码不能在中途抢占，但并发有界。

## 体验验收

1. 快速连续滚动首页再回滚，检查封面、头像和刷新落位；内存告警后图片应正常重新加载。
2. 打开有续播位置的视频但不播放，拖动后关闭：不应因此上传拖动位置或“已看完”。
3. 正常播放后暂停、退出和快速重开，检查历史进度；倍速播放不应加密心跳发送频率。
4. 登录/退出后重新打开同一个视频，播放清单应按当前账号重新获取。
5. 手动选择一次“不感兴趣”，确认卡片在成功后移除；网络失败不应自动重复写反馈。
