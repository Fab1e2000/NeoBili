## 样本范围

实现契约汇总已有协议分析与操作采集。它描述各项结论的依据，不记录开发者在某次整理中执行过的命令，也不代表当前代码已完成真实环境验收。

| 来源 | 可以支持的结论 | 不能据此推断 |
| --- | --- | --- |
| iOS 8.89.0 / build 88900100 静态样本 | 该样本中的符号、字段、请求构造和调用关系 | 最新官方版本或当前服务器一定沿用相同逻辑 |
| 官方 9.13.0 / build 91300100 操作采集 | 已注明操作条件下实际发出的请求与响应 | 所有账号、设备或操作场景均相同 |
| 9.13 / build 91300300 既有样本 | 各条目明确标注的对照结果 | 可以替代 build 91300100 的证据 |
| NeoBili 当前源码及受控测试 | 本项目采用的规则和可复现行为 | 推荐效果、账号权限和硬件播放已验收 |

具体证据位置随契约条目保存。原始抓包及带凭据的材料留在仓库外；`DerivedData/Validation/` 下的旧研究索引只用于追溯，不是新开发者构建项目所需的输入。

## 解释证据时的限制

HTTP、Ktor、Moss、日志上传、崩溃提交和 IM 同步各有独立请求路径，不能由一个入口推断整个功能。某个符号扫描结果为零，只说明所用工具和范围内未找到，不能证明运行时不存在调用。Swift 惰性槽、ObjC 分派和 thunk 链尤其需要进一步追踪。

已被后续证据修正的推断，以各主题章节的当前说明为准。例如，Ktor 成员和请求类型写入方、HTTP 多域名门控、日志配置注入点均应按已定位的调用链描述；仍缺运行期值的项目继续保留验证条件。契约条目数量、覆盖表行数或未决词出现次数均不能用作完成度。
