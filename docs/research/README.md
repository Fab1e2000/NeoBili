## 怎样判断结论强度

- **静态证据**：在特定版本的反汇编、描述符或调用链中定位到逻辑。它说明代码存在，不证明这次请求实际走过该分支。
- **运行观察**：在注明操作条件的请求或日志中看到结果。不要将一个账号、设备或时间点的结果推广为服务端保证。
- **接口接受**：请求获得成功回执。它不等于推荐兴趣已更新，也不等于与官方客户端完全一致。
- **实现和回归**：当前代码采用规则，且受控测试通过。真实账号、媒体播放和推荐效果仍有独立验收边界。
- **待验证**：已有线索但证据不足。保留问题和验证条件，不用默认值填补未知语义。

## 常用术语

| 文档用词 | 含义 |
| --- | --- |
| builder / assembler | 组装请求字段的函数 |
| provider / consumer | 数据提供方 / 实际读取并使用数据的代码 |
| endpoint | 请求的接口地址 |
| metadata | 随请求发送的附加字段，常见于 gRPC 请求头 |
| descriptor | Protobuf 消息字段编号及类型的描述 |
| scope | 凭据、缓存或配置的适用范围 |
| generation / 登录代际 | 用于识别账号切换或请求作废的标记 |
| 闭合 / 闭环 | 原记录中表示某条证据链已追到所述边界；不表示整个功能或真实环境验收完成 |
| task 编号、批次、席位 | 原研究的来源标识，不是当前待执行任务或权限要求 |
| RVA / 函数地址 | 定位特定二进制样本中的代码；换版本后不能直接复用 |

## 维护规则

保留样本版本、可定位的证据、推断条件和未知项。更新实现时修改对应契约与核查章节；新增观察时写明操作和变量。不要将构建日志、个人凭据或临时工作流水写进研究文档。发布说明保留历史事实，不随当前实现追改。
